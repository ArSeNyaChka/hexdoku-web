# HexDoku

Судоку для браузера: классическое **9×9** и шестнадцатеричное **16×16** с цифрами `0–F`.
Чистые HTML/CSS/JS, без сборки и без бэкенда — можно открыть двойным кликом или
выложить на GitHub Pages как есть.

Живой пример: `https://<username>.github.io/<repo>/`

## Возможности

- Два размера поля: 9×9 (цифры 1–9, блоки 3×3) и 16×16 (цифры 0–F, блоки 4×4).
- Четыре уровня сложности; у каждого задания **ровно одно решение** — это
  доказывается перебором на этапе генерации.
- Заметки-кандидаты, автозаметки при вводе, отмена/повтор, подсказки, пауза.
- Кисть: зарядили цифру и ставите её кликами (или свайпом) по клеткам.
  Если включить заметки — кисть расставляет кандидатов.
- Автопереход на следующую пустую клетку после ввода — отключается в настройках.
- Подсветка строки/столбца/блока выбранной клетки, одинаковых цифр и конфликтов.
- Таймер, счётчик ошибок, рекорды по каждому режиму.
- Серия дней в стиле GitHub: сетка за 18 недель, у дня три состояния —
  ничего не решено, решён один режим (9×9 или 16×16), решены оба.
- Прогресс и настройки сохраняются в `localStorage` — игру можно закрыть и продолжить.
- Тёмная и светлая тема, адаптивная вёрстка, управление с телефона (свайп по клеткам).

## Управление

| Действие | Мышь/тач | Клавиатура |
| --- | --- | --- |
| Выбрать клетку | клик / свайп | стрелки |
| Ввести цифру | кнопка на панели | `0-9`, `A-F` |
| Стереть | ⌫ | `Backspace`, `Delete`, `Space` |
| Заметки | ✎ | `N` |
| Кисть (поставить краску / сменить её) | ◉, затем клик по клетке | `V` |
| Подсказка | ? | `H` |
| Пауза | ❚❚ | `P` |
| Отменить / вернуть | ↶ ↷ | `Ctrl+Z`, `Ctrl+Shift+Z` |

## Запуск локально

Статика, поэтому достаточно любого HTTP-сервера:

```bash
python3 -m http.server 8000
# или
npx serve .
```

Открыть <http://localhost:8000>. Без сервера тоже работает: `index.html`
подключает скрипты по относительным путям.

## Тесты

Тесты на встроенном раннере Node (>= 18), зависимостей нет:

```bash
node --test tests/
```

- `tests/engine.test.mjs` — корректность заполнения, единственность решения,
  конфликты, алфавиты.
- `tests/ui.test.mjs` — UI на минимальном DOM-стабе: ввод, стирание, undo/redo,
  заметки, переключение 9×9 → 16×16, победа, сохранение и восстановление.

## Деплой на GitHub Pages

1. Запушить этот каталог в репозиторий (`main`).
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
3. **Branch: `main` / `/ (root)` → Save**.
4. Сайт будет на `https://<username>.github.io/<repo>/`.

Собирать нечего: `index.html`, `css/` и `js/` лежат в корне репозитория,
пути в разметке относительные (`./css/...`, `./js/...`), поэтому сайт одинаково
работает и в корне домена, и в подпапке `<repo>/`.

## Как устроена генерация

`js/sudoku.js` не зависит от DOM и работает и в браузере, и в Node.

1. **Решение.** Случайный бэктрекинг со стратегией «наименьший остаток»;
   если на 16×16 он не укладывается в лимит узлов, берётся канонический
   латинский квадрат и перемешивается допустимыми симметриями (полосы, строки
   внутри полосы, столбцы, транспонирование, перестановка символов) — отказ
   невозможен.
2. **Задание.** Клетки удаляются по одной; каждое удаление принимается, только
   если перебор доказал единственность оставшегося решения. Кандидаты
   поддерживаются инкрементально через счётчики запретов, поэтому проверка
   единственности не превращается в минуты перебора.
3. **Пороги сложности** для 16×16 ограничены практически: ниже ~100 подсказок
   жадное удаление деградирует, поэтому «Эксперт» — 106 клеток из 256.

Генерация выполняется в основном потоке и занимает от десятков миллисекунд
(9×9, 16×16 лёгкий) до нескольких секунд (16×16 эксперт); на это время
показывается оверлей.

## Структура

```
index.html      разметка и точки подключения
css/style.css   оформление, темы, адаптив
js/sudoku.js    движок: генерация, единственность, конфликты
js/app.js       UI: ввод, заметки, история, таймер, хранилище
tests/          тесты движка и UI (node --test)
```
